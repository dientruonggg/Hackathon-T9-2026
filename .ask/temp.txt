Judging Criteria
Every project is judged twice on the same four criteria below, scored 1 to 5 each.

In Da Nang on the day. After the 4:00 p.m. cut-off, the local panel scores every submission from its 2-minute video and written entry, using this rubric, and selects 5–6 finalists. Finalists demo live on stage at 5:00 p.m. (2 minutes demo, 4–5 minutes of questions), the panel deliberates, and the Da Nang prizes are awarded at 6:15 p.m. A judge does not score a team that includes a colleague from their own company.

Globally after the event. AI Tinkerers judges review every eligible project from every city separately, using the same criteria, for the global awards.

Criterion	What We’re Looking For	Scoring (1–5)
Core Requirements & Functionality	Does the project deliver a working agent inside a place where people already work, talk, or live? Does the core workflow function end to end?	1: The project does not run or does not demonstrate a functional agent.
2: Parts of the project run, but the core workflow or environment integration is incomplete.
3: A basic end-to-end agent works in the intended environment, with limitations or bugs.
4: The project works reliably and demonstrates a complete agent experience with only minor issues.
5: The project is robust, reliable, and fully functional within its intended environment.
Innovation & Theme Alignment	Does the project explore a compelling new place or interaction for agents? Does the environment materially improve what the agent can do?	1: The project is essentially a generic chatbot or automation; the selected environment is irrelevant.
2: The agent appears in an eligible environment, but the environment mostly serves as a wrapper.
3: The project clearly addresses the theme, and its environment adds meaningful value.
4: The environment shapes the core workflow and enables an original agent experience.
5: The project reveals a surprising new agent pattern whose central value could not be reproduced in a standalone chatbox.
Technical Execution & Integration	Consider the code, architecture, reliability, tool use, data handling, and depth of integration with the selected environment.	1: Little or no technical execution is evident; the submission is primarily conceptual or mocked.
2: The implementation is basic, unstable, or relies on superficial integrations.
3: The project demonstrates solid technical execution and working integrations, with some rough edges.
4: The project is well engineered, reliable, and integrates its tools, data, and environment effectively.
5: The project demonstrates exceptional engineering, including robust orchestration, thoughtful failure handling, and a deeply integrated architecture.
Usefulness & Agentic Experience	Does the project create clear value for its intended users? Is the agent intuitive, effective, and appropriate for the environment in which it operates?	1: The use case is unclear, and the agent provides little meaningful value or interaction.
2: The project addresses a recognizable use case, but the agent’s contribution is limited or largely resembles basic prompt and response.
3: The project is useful, the interaction is understandable, and the agent performs meaningful actions with reasonable user control.
4: The project solves a clear problem, and the agent feels native to its environment while creating a strong interaction between people and AI.
5: The project unlocks substantial value through an agent experience designed specifically for its environment, using context intelligently while remaining clear and controllable.

Handbook
Event rules, schedule notes, submission guidance, and practical details in one place.

The Challenge
Build an agent for a place people already work, talk, or live, then make it meaningfully more useful because of that context.

That could mean the web, mobile, Slack, Teams, messaging, browsers, workplace software, voice, wearables, robotics, or an entirely new environment.

Build Something Real
The goal is a working prototype that can be demonstrated by the end of the day. Keep the scope tight, prioritize the core interaction, and make sure the agent’s environment is essential to the experience.

You may use any technical stack. The shared starter repository, sponsor resources, credits, and technical documentation will be added here before build day.

Build Eligibility
Every submitted project must be a net-new build created during the official hackathon period.

Teams may use existing templates, reusable components, libraries, prompts, starter code, or other building blocks. However, the project being submitted and its core functionality must be built during the event. A pre-existing project cannot be resubmitted or extended and entered as a new hackathon project.

Teams should be prepared to explain which parts of their project were created during the hackathon.

Your Submission
Every team must submit:

A project title
A written description
A public GitHub repository
A two-minute demonstration video
A social media post about the project tagging the event partners
Every team must complete its submission in this portal by 4:00 p.m. on Saturday 12 September. For the Da Nang prizes that cut-off is final: the local panel scores what is in the portal at 4:00 p.m., and anything added or changed after that is not considered for the local prizes.

Every eligible project also enters the same global competition, judged separately by AI Tinkerers after the event.

Judging in Da Nang
Both the local panel and the global judges use the four criteria in the Judging Criteria section, scored 1 to 5 each: Core Requirements & Functionality, Innovation & Theme Alignment, Technical Execution & Integration, and Usefulness & Agentic Experience.

16:00–16:45 The local panel (Trung Huynh, Blaze AI; Cuong Pham, Cohost AI; Viet Ha, Dewly AI) reviews every submission from its 2-minute video and written entry, and selects 5–6 finalists.
16:45 Finalists are announced and get 10–15 minutes to prepare.
17:00–17:45 Each finalist demos live on stage: 2 minutes to demo, then 4–5 minutes of questions from the panel.
17:45–18:15 The panel deliberates.
18:15–19:00 Prizes and close.
A judge does not score a team that includes a colleague from their own company; the remaining judges’ scores are averaged.

Your 2-minute video
The local panel judges from the video, so treat it as your main pitch. Show the agent working in its real environment, end to end. Say who it is for and why it belongs there rather than in a chat window. Show the integration, not slides.

Keep the file small (720p, under 100 MB) and upload it to YouTube (unlisted is fine) or Loom as soon as your demo is ready rather than at 3:55.
